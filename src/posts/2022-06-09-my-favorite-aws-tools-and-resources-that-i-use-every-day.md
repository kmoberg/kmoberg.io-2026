<p>Working as a developer and cloud platform engineer working with AWS, I use a ton of tools every day. A lot of these are OS agnostic, but there are some that are not — I’m a Mac user: sorry.</p><h3 id="terminal-iterm2-fig-starship-">Terminal: iTerm2 + Fig + Starship = ❤️</h3><p>My main tool is my terminal. I use it all day, every day and it is probably my most important tool, which is also why it has gone through a ton of modifications over the years and has now gotten to a point where I’m mostly happy with it.</p><p>As for which shell I’m using, I’m still using ZSH with Oh-my-zsh installed, but with mostly default settings and a theme applied.</p><figure class="kg-card kg-image-card kg-card-hascaption"><img src="/images/ghost/2025/08/1-dnht6pxjykkr-2h9qqojxa.png" class="kg-image" alt loading="lazy" width="1177" height="735"><figcaption>My Terminal&nbsp;Setup</figcaption></figure><hr><h4 id="iterm2">iTerm2</h4><p>iTerm is the base of the terminal. It has a ton more options than the built in terminal, although I rarely use most of them these days.</p><p><strong>Cost: Free!</strong> from <a href="https://iterm2.com]%28https://iterm2.com/%29" rel="nofollow noopener noopener">https://iterm2.com</a></p><hr><h3 id="starship">Starship</h3><p>Starship is where the customization begins! Starship a customizable prompt that gives me a ton of information at a glance. The prompt is very much context aware, and will change depending on what folder you are in, displaying only relevant information to you.</p><figure class="kg-card kg-image-card kg-card-hascaption"><img src="/images/ghost/2025/08/1--ywesroneywdyfamenuiyw.gif" class="kg-image" alt loading="lazy" width="1526" height="956"><figcaption>Starship.rs in&nbsp;action</figcaption></figure><p>In my case I display things like current AWS profile in use, git status, and battery information if I’m running low.</p><figure class="kg-card kg-image-card kg-card-hascaption"><img src="/images/ghost/2025/08/1-rs7z8qm1enntyuinbnneia.png" class="kg-image" alt loading="lazy" width="1647" height="1160"><figcaption>The starship config&nbsp;file</figcaption></figure><p><strong>Cost: Free</strong> from <a href="https://starship.rs/]%28https://starship.rs/%29" rel="nofollow noopener noopener">https://starship.rs/</a></p><hr><h3 id="fig">Fig</h3><p>This is my latest tool in my arsenal and it’s fantastic!</p><p>Fig is a terminal addition that adds IDE-style autocomplete to your existing terminal. I know you don’t <strong>need</strong> this functionality, but boy is it nice to have in a lot of situations when you can’t exactly remember a command or what the heck you named your file or folder.</p><p>Fig also allows you to create custom shortcuts and commands the same way aliases let you execute commands more efficiently. It’s hard to stay enough good things about Fig and it’s well worth a try!</p><figure class="kg-card kg-image-card kg-card-hascaption"><img src="/images/ghost/2025/08/1-bh_wah1c-aqdig7zmaoofg.gif" class="kg-image" alt loading="lazy" width="1202" height="820"><figcaption>Demo of&nbsp;fig</figcaption></figure><p><strong>Cost: Free</strong> from <a href="https://fig.io" rel="noopener">https://fig.io</a></p><hr><h3 id="jetbrains">Jetbrains</h3><p>I’ve used pretty much all the code- and text editors as well as IDEs that are on the market. I was a die-hard VScode user since one of the earliest betas, but after a friend showed me the power if the Jetbrains suite, it’s hard to go back. Jetbrains offers a myriad of various IDEs for different languages, but they all share the same basic concepts and functionality. It is extremely customizable thanks to a well stocked plugin library from 3rd party developers as well as Jetbrains them selves and as as result, a ton of their software have gotten a permanent place in my dock as I use it on the daily.</p><figure class="kg-card kg-image-card kg-card-hascaption"><img src="/images/ghost/2025/08/1-bmsnz8s5j-c1v-4m3h7zhw.png" class="kg-image" alt loading="lazy" width="540" height="131"><figcaption>The dock on my Mac always have a number of Jetbrains apps.</figcaption></figure><p>Specifically my most used applications include PyCharm, GoLand, WebStorm and DataGrip. As I’m also still responsible for some PHP apps, PHPStorm is also still used, but not as much.</p><p>If you haven’t tried out DataGrip yet, it got a significant revamp a while back and is honestly one of the best database management tools I’ve used.</p><p><strong>Cost: €649 per year, ex. VAT.</strong> (For Students: <strong>FREE!</strong>) from <a href="https://www.jetbrains.com/]%28https://www.jetbrains.com/%29" rel="nofollow noopener noopener">https://www.jetbrains.com/</a></p><hr><h3 id="github-copilot">Github Copilot</h3><p>This is going to cause some controversy I’m sure. Other developers I know claim Copilot is terrible and makes it look like a junior developer wrote the code and is terrible insecure. I disagree. If you think this way, you’re not using Copilot right and you’re just accepting whatever Copilot suggests without no critical thought. That’s not how it’s designed, and not how you should be using it.</p><p>Copilot can help you <strong>significantly</strong> speed up your workflow by suggesting the code you are going to type. In the example below, I’m creating a Terraform security group for AWS. I specify the name and ingress, and Copilot suggests the next steps. However, as you can see, it suggests the wrong ports, and I’m not blindly accepting it. You need to be weary of what it suggests and correct what needs to be corrected. However, it even so, it saves me significant time when building these code blocks.</p><figure class="kg-card kg-image-card kg-card-hascaption"><img src="/images/ghost/2025/08/1-s7fh2mbvflswuugrexes8w.gif" class="kg-image" alt loading="lazy" width="796" height="524"><figcaption>Github Copilot&nbsp;Demo</figcaption></figure><p>There are some significant privacy concerns about using copilot, as copilot transmit a good amount of telemetry when it is used, and its suggestions are based on other peoples open-source code submitted to GitHub, so if you are developing top-secret government secrets, I would read the privacy policy before blindly jumping into Copilot. However, if you’re already putting your code in Github SaaS and not hosting your own server, and especially if you’re using public repos, the telemetry Copilot uses should be no huge privacy concern.</p><p><strong>Cost: Free</strong> (requires invite) from <a href="https://copilot.github.com/]%28https://copilot.github.com/%29" rel="nofollow noopener noopener">https://copilot.github.com/</a></p><hr><h3 id="aws-cli-and-aws-shell-">AWS CLI (and aws-shell)</h3><p>AWS has a great CLI, but what’s even cooler is “<strong>aws-shell</strong>”! From AWS labs, you can run an interactive shell that connects to your AWS account and from there manipulate it as you wish. It provides auto completion not only for commands, but also for resource names and is incredibly powerful!</p><figure class="kg-card kg-image-card kg-card-hascaption"><img src="/images/ghost/2025/08/1-4kb_845g2gerkwo1gwzf-g.gif" class="kg-image" alt loading="lazy" width="600" height="387"><figcaption>AWS Shell&nbsp;Demo</figcaption></figure><p>I’ll be the first to admit that I typically just use the normal CLI, but as soon as I have to deal with instance names and more, the shell is a fantastic tool to be able to use!</p><p>In case you don’t know — thanks to AWS “API First” philosophy, any resource in AWS should be available as an API and in the CLI, so anything you do in the console should have an API available to you.</p><p><strong>Cost: Free</strong> from <a href="https://github.com/awslabs/aws-shell]%28https://github.com/awslabs/aws-shell%29" rel="nofollow noopener noopener">https://github.com/awslabs/aws-shell</a></p><hr><h3 id="infrastructure-as-code-iac-terraform-and-pulumi">Infrastructure as Code (IaC) — Terraform and Pulumi</h3><p>If you’re working with cloud and haven’t looked at infrastructure as code yet — you need to do so. Today. If you’re still configuring your infrastructure by clicking in the console, or running a single CLI command here and there to maintain your infrastructure, it’s time to move on — trust me.</p><p>Infrastructure as Code, like the name suggest, allow you to define your infrastructure in code. This means it can be checked into version control, and that it is easily reproducible. It makes it incredibly easy to organize and make sure that knowledge isn’t lost when someone leaves the company. The idea is that the infrastructure is *immutable* and should not change after it has been deployed without a redeploy or replacement.</p><p>There are multiple tools available for this task such as CloudFormation, Chef, Puppet and more, but I’d like to recommend two sets of tools: Terraform and Pulumi.</p><p>Terraform is probably the most well-known IaC tool on the market in 2022. It has a very robust set of tools, providers and developer support available making it incredibly powerful and easy to get started with, building your infrastructure. Terraform is made by Hashicorp, a company known for providing robust and well-tested infrastructure tools. You write your code in HCL (Hashicorp Configuration Language) a custom language that is easy to write and easy to read, but there is also a JSON version available if you absolutely prefer JSON for some reason.</p><p>In my opinion, Terraform is *perfect* for infrastructure or someone in operations starting on their IaC journey, or if you have a team of infrastructure people working on this. It is extremely powerful and extendable, and provides the tools a platform team needs.</p><p>Terraform is a fantastic companion to AWS and especially if you’re testing new things and labbing a project as it is incredibly easy to create a new resource and then destroy everything afterwards.</p><figure class="kg-card kg-image-card kg-card-hascaption"><img src="/images/ghost/2025/08/1-v3qz_3ds7ng2w9lafmfefg.png" class="kg-image" alt loading="lazy" width="1232" height="1682"><figcaption>Example terraform</figcaption></figure><p>However, if you’re a developer with limited or no infrastructure experience, let me suggest an alternative to you: Pulumi.</p><p>Unlike Terraform, Pulumi doesn’t have use it’s own markup language, but instead extends the programming language you’re already working in, such as Python, Go, Typescript, C# or Java! Allowing you to define your infrastructure in a language you’re already familiar with.</p><p>Pulumi has a number of other extremely powerful tooling as well, allowing you to more easily deal with expressions, and logic, not directly possibly in Terraform.</p><p>For a lot of developers, it is much easier to get started with Pulumi over Terraform, so it’s worth looking into. However, as Pulumi is a newer tool, it is not as well-known as Terraform, but it **uses terraform providers** meaning it has the same support for infrastructure as Terraform.</p><figure class="kg-card kg-image-card kg-card-hascaption"><img src="/images/ghost/2025/08/1-uqiigtcvowedxbgvkglzwq.png" class="kg-image" alt loading="lazy" width="564" height="458"><figcaption>Pulumi using&nbsp;Python</figcaption></figure><p><strong>Cost: FREE!</strong> from <a href="https://www.pulumi.com/]%28https://www.pulumi.com/%29" rel="nofollow noopener noopener">https://www.pulumi.com/</a> and <a href="https://www.terraform.io/]%28https://www.terraform.io/%29" rel="nofollow noopener noopener">https://www.terraform.io</a><br>(Terraform has some paid cloud functionality for working with enterprise functionality)</p><hr><h3 id="alfred">Alfred</h3><p>Ok — on to some very Mac specific apps I use, that are incredible. First of all: Alfred.</p><figure class="kg-card kg-image-card"><img src="/images/ghost/2025/08/1-5jv73l0-pg2ospjbbno6ug-jpeg.jpg" class="kg-image" alt loading="lazy" width="594" height="388"></figure><p>I first used Alfred on my very first MacBook, in 2006 — back when Spotlight on the Mac in OS X 10.4 was awful and took multiple minutes to launch an application. However, once 10.6 and 10.7 rolled around, Spotlight got to a point where I really didn’t feel I needed to install Alfred anymore, since I was just using it as a fancy app launcher anyway.</p><p>That was a mistake.</p><p>I started using Alfred again this year, after not having used it for 10 years, and boy has it been great! Yes — Alfred can function as a fancy app launcher, but that’s not why you want it. You want Alfred for all the small functionality here and there you can do. Like moving a file from one folder to another with two presses, or searching through Apple Music instantly from your keyboard and without ever leaving your current application.</p><figure class="kg-card kg-image-card kg-card-hascaption"><img src="/images/ghost/2025/08/1-crfnogln9uuduq_ctotzeq.png" class="kg-image" alt loading="lazy" width="2000" height="1125"><figcaption>Alfred in&nbsp;use</figcaption></figure><p>Alfred is incredibly powerful in ways you could probably never imagine. It’s FREE except for some functionality, so it’s well worth you trying it out!</p><p><strong>Cost: FREE</strong> (some paid features) from <a href="https://www.alfredapp.com/" rel="nofollow noopener">https://www.alfredapp.com/</a></p><hr><h3 id="snippetslab">Snippetslab</h3><p>This is a small useful utility that I have yet to utilize to it’s full potential, but it’s a very lightweight and useful application for storing snippets of code for re usability.</p><figure class="kg-card kg-image-card kg-card-hascaption"><img src="/images/ghost/2025/08/1-4gzkhmgslfyedigibnjrpw.png" class="kg-image" alt loading="lazy" width="1632" height="711"><figcaption>Snippetslab</figcaption></figure><p>It has built in integration with Github Gists, allowing you to instantly publish and share code with others, as well as syntax highlighting for a ton of languages.</p><p>However, what makes Snippetslab most useful to me, is the incredible Alfred integration! With a simple <code>CMD + Space</code>, then type in <code>snip &lt;search&gt; </code>followed by ENTER to instantly insert a snippet.</p><figure class="kg-card kg-image-card"><img src="/images/ghost/2025/08/1-hhornruizio3fkzc5r81cq.gif" class="kg-image" alt loading="lazy" width="800" height="706"></figure><p>There are tons of other snippet managers around, however what makes this one great, is the fantastic Alfred integration.</p><p><strong>Cost: $9.99</strong> from <a href="https://www.renfei.org/snippets-lab/]%28https://www.renfei.org/snippets-lab/%29" rel="nofollow noopener noopener">https://www.renfei.org/snippets-lab/</a> or on <a href="https://setapp.com/" rel="noopener">SetApp</a></p><hr><h3 id="dropshare">Dropshare</h3><p>There are again plenty of uploading tools available, but Dropshare has been my favorite for a while. It’s a simple menubar application that allows you to easily upload screenshots, documents, videos, or what you want to a myriad of destinations, including AWS S3!</p><figure class="kg-card kg-image-card"><img src="/images/ghost/2025/08/1-wzyzke8hjjbnbzp6zcd3xa.png" class="kg-image" alt loading="lazy" width="1587" height="1545"></figure><p>It’s also highly customizable, including giving you the ability to automatically shorten URLs to a custom domain.</p><p><strong>Cost: $24.99</strong> from <a href="https://dropshare.app]%28https://dropshare.app%29" rel="nofollow noopener noopener">https://dropshare.app</a> or on <a href="https://setapp.com/" rel="noopener">SetApp</a></p><hr><h3 id="conclusion">Conclusion</h3><p>These are just a few of my every day applications that I use. I have a plan on expanding this series with a few more posts with more of the really useful Mac applications that I’ve found over the years.</p>
